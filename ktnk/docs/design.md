# 作業予定入力システム 設計メモ

## 決定事項

- 職人側フォームは完全公開とする
- 現場は1つだけ扱う
- 同じ作業日・同じ一次会社の予定は1件だけ持つ
- 再送信された場合は、既存予定を削除して新しい内容で上書きする
- 1回の送信が、その一次会社のその日の全作業予定を表す
- 1つの一次会社に対して、複数の二次会社を登録できる
- 作業エリアと作業内容は予定グループ全体で1つずつ持つ
- 作業エリアと作業内容は自由入力とする
- 作業なしは協力会社本人が入力する
- 作業なしの場合、来場予定日・作業エリア・作業内容・人数・二次会社は任意入力とする
- 締め時刻は20:00とする
- 送信後に「同じ内容で別日を入力」できるようにする
- 修正履歴・再送信履歴は残さない
- 職人側フォームの日付入力は、当面は1日だけとする
- APIとDBは、将来の複数日登録再開に備えて期間登録に対応したまま残す
- 作業エリア・作業内容は「前回と同じ」を選べる

## DB設計案

### schedule_groups

一次会社単位の予定グループです。

| column | type | note |
| --- | --- | --- |
| id | uuid | primary key |
| work_date | date | 作業日 |
| status | text | `work` または `no_work` |
| primary_company | text | 一次会社名。CSVの表記をそのまま保存 |
| primary_count | integer | 一次会社人数 |
| work_area | text | 作業エリア |
| work_content | text | 作業内容 |
| next_visit_date | date | 任意 |
| next_primary_count | integer | 任意 |
| next_work_content | text | 任意 |
| created_at | timestamptz | 作成日時 |
| updated_at | timestamptz | 更新日時 |

unique制約:

```sql
unique (work_date, primary_company)
```

### schedule_subcompanies

予定グループに紐づく二次会社人数です。

| column | type | note |
| --- | --- | --- |
| id | uuid | primary key |
| schedule_group_id | uuid | schedule_groups.id |
| kind | text | `current` または `next_visit` |
| secondary_company | text | 二次会社名。空欄も許容 |
| worker_count | integer | 人数 |
| sort_order | integer | 表示順 |

`kind = current` は作業ありの当日二次会社、`kind = next_visit` は作業なし時の次回来場予定二次会社として扱います。

## 上書きフロー

`POST /api/schedules` で登録します。

1. 入力値をサーバー側で検証する
2. `work_date + primary_company` に一致する既存 `schedule_groups` を検索する
3. 既存があれば、紐づく `schedule_subcompanies` を削除する
4. `schedule_groups` をupsertする
5. 新しい `schedule_subcompanies` をinsertする

履歴は残さない前提のため、削除して差し替える設計にします。

## 複数日登録

現在の職人側フォームでは単日入力だけ表示します。

内部APIは開始日から終了日までの日付をサーバー側で展開し、日付ごとに `schedule_groups` を作成できる構造のまま残します。

期間入力を復活させる場合、土日除外は任意チェックにします。建設現場では土曜作業があるため、初期値は除外しません。

## 送信後の別日入力

送信完了後に以下のボタンを出します。

- 同じ内容で別日を入力
- 新しく入力する

`同じ内容で別日を入力` は、会社・人数・作業内容・作業エリアを保持し、日付だけ変更可能な状態に戻します。

## Excel出力

Web管理画面から `.xlsx` を出力します。

- 日付ごとにシートを分ける
- 二次会社ごとに1行出力する
- 二次会社なしの場合は二次会社欄を空欄で1行出力する
- 作業なしで来場予定の二次会社が複数ある場合は、来場予定二次会社ごとに1行出力する

列定義:

| 列 | 項目 |
| --- | --- |
| A | 作業日 |
| B | 予定 |
| C | 一次会社 |
| D | 一次会社人数 |
| E | 二次会社 |
| F | 二次会社人数 |
| G | 作業エリア |
| H | 作業内容 |
| I | 来場予定日 |
| J | 来場予定一次会社人数 |
| K | 来場予定二次会社 |
| L | 来場予定二次会社人数 |
| M | 来場予定作業エリア |
| N | 来場予定作業内容 |
| O | 登録日時 |
| P | 更新日時 |

マスタExcel側では、取込時に以下を追加します。

| 列 | 項目 |
| --- | --- |
| Q | 取込日時 |
| R | 取込元ファイル |

## Box CSV取得

`GET /api/companies` でBox公開CSVを取得します。

- サーバー側でCSVを取得する
- ブラウザからBoxへ直接アクセスしない
- CSVは一定時間キャッシュする
- 取得失敗時は直近キャッシュがあればそれを返す
- キャッシュもない場合はフォームにエラーを表示する
- 会社名は正規化しない

## 後から変えると影響が大きい点

- 複数現場対応を追加する場合、ほぼ全テーブルに `site_id` が必要になる
- `work_date + primary_company` 上書きから履歴管理へ変える場合、unique制約と管理画面の見せ方を変える必要がある
- 作業エリア・作業内容を二次会社ごとに持たせる場合、テーブル構造とExcel出力が変わる
- 作業なし時の来場予定を複数日持たせる場合、来場予定専用テーブルが必要になる
- Excel側を正データにする運用へ変える場合、Web DBとの同期設計が必要になる
